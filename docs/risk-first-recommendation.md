# 从证据覆盖研究收敛到风险筛查（2026-11-23）

用户决策：这是推荐系统，不需要证明每个细节都满足。先筛掉明确不能接受的冲突，再对剩下的候选按证据匹配程度推荐。没有查到雷点不代表没有雷点。

## 本轮已实现

1. 正式规则引擎返回 `recommendation_status`、`evidence_summary`、`exclusion_reasons`。支持权重、风险权重、风险主题、信息缺口单独列出。mixed 的风险不会被正面证据从摘要中抹掉。没有偏好时标为 hard_conditions_only，不能声称偏好已获支持。
2. 现有硬条件排除、未知费用待核实、每主题支持/风险分别最多贡献一次、净分排序继续保留。此次没有改变排序算法。返回字段使混合证据和无证据即使同为零分也能区分。
3. 新增独立 `risk_policy.apply_reviewed_conflicts`：仅供受信任的本地人工审核调用。审核须有候选 ID、审核者、不可接受条件、理由和逐字引用。来源与需求（含原话）指纹必须匹配；改动任何需求或来源后旧审核作废。无记录时保留原结果。引用缺失、来源未知、重复决定、模型来源或陈旧审核均拒绝。
4. 被排除候选仍在 excluded 中保留来源和审核原因；正面分数不能抵消已审核的冲突。所有候选排除后不会强行补推荐。

审核记录是受信任输入，`origin=human_review` 不是身份认证机制；不能接受模型自行设置这个字段，也不能将其直接开放为任意 HTTP 参数。代码只验证记录与证据绑定，不能证明审核者的语义判断正确、来源真实或仍然有效。

## 可复现演示

运行 `.venv/bin/python scripts/demo_risk_policy.py`，无数据库或模型调用。输出也保存于 `evaluation/risk-policy-demo.json`。

演示使用现有虚构 A/B/C/D，以及更明确的虚构需求“不能接受已有视频会议掉线记录的房源”。这与“不能经常掉线”不同：单次旧评论不足以证明经常掉线，所以示例不做这一推断。

- B 因不允许猫，继续硬条件排除。
- D 在无审核时保留，显示视频会议风险。
- 手写审核样例引用 D 的两次掉线记录，因虚构用户明确拒绝这类记录，D 移入排除列表。此为手写审核流程样例，没有声称真实用户审核或真实房源质量已经核实。
- A 保留，安静主题同时有正反证据，风险仍可见。
- C 继续待核实；网络资料缺失不能记为网络良好。

## 边界与后续

人工审核排除入口目前仅在独立后端模块和离线演示中；尚未接入网页、HTTP 或 RAG 主链路。网页仍使用原有展示，新增摘要已由规则结果携带但没有新增审核界面。原有未支持需求拦截仍有效，复杂硬性细节不会被静默当作已经支持。

不启用此前验证未通过的模型自动淘汰。只有相关性高、评论多、或者来源日期新，都不足以自动等同于“明确不能接受的冲突”；还要审查归属、用户意图、观察条件、重复来源和修复情况。

下一步是把风险摘要和排除原因做成可理解的页面展示，并设计明确的用户排除操作及失效提示，再接入完整管线。先让用户能看到依据并控制排除，避免继续在小型合成集上反复微调语义标签。没有设定新的检索权重。

## 验证

91 项测试通过（含数据库测试），本地回归峰值 RSS 52.88 MiB，真实模型调用 0。新增测试：无审核不排除风险、审核冲突排除且不修改原结果、拒绝模型标记、需求/原话/来源变更使审核失效、伪造引用/未知候选/重复审核拒绝、风险与缺口区分、全排除无强行推荐、无偏好不声称支持。

## 面试故事

从“如何证明细节完全满足”转向“先识别不可接受的冲突，再按有限证据推荐”。明确区分检索相关性和推荐意义，保留未知状态；将不可逆于当前推荐结果的淘汰建立在可追溯审核上，模型风险标签只作为辅助。此次完成的是规则和审核接口，不包装成已经实现的自动语义筛查。

## 页面接入更新（2026-11-23）

已将风险、信息缺口摘要加入房源卡片。在证据详情中可填写不能接受的情况、选择原文、填写理由并确认用户排除。已排除分类显示用户理由，详情可撤销；硬条件排除不能用撤销用户操作绕过。

新增 `/api/review-exclusion` 仅接受选择字段，不接受调用方指定 origin/reviewer；后端重新读取候选，验证逐字引用和来源/需求指纹，明确返回 `user_exclusion`、`user_choice_not_verified_fact`。这是本机用户选择，不是独立人工审核认证、模型判定或事实验证。沿用同源/loopback 请求限制，不设计多用户身份认证。

规则及 RAG 结果均携带来源/需求指纹；用户排除在当前结果副本上操作，不重新调用模型。被排除候选的解释从展示结果中移除，撤销后从本次原结果恢复。导出包含用户决定、原文、原因与指纹；RAG 顶层 excluded 与 comparison.excluded 保持同步。决定仅在当前页面内存中保存，不写数据库、不使用 localStorage；重新分析、修改条件/原话、切换数据集或刷新后清除。异步审核若返回时原结果已失效，不应用旧决定。

浏览器实测：必填提示、D 排除（已知满足 2→1、已排除 1→2）、原文和理由展示、撤销恢复、重新排除后改原话清除。无浏览器错误日志。截图 `docs/screenshots/user-exclusion.png`。未执行移动端或真实付费 RAG 端到端测试，下载文件本轮未再次验证。

94 项完整回归测试通过（含 5 项数据库测试），峰值 RSS 53.20 MiB，0 次真实模型调用。随后对用户决定标记及导出一致性的微调，相关 11 项后端测试通过。临时预览使用不加载密钥/数据库的 8789 端口，任务结束关闭。
