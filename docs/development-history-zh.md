# ChoiceMatch

基于结构化信息与可追溯证据的个性化选择平台。求职作品的首个场景为租房，芝加哥仅作为虚构演示背景；住宿将作为第二个场景验证核心复用，汽车属于后续范围。

灵感来自早期 Airbnb 数据分析项目，以及浏览租房平台时遇到的信息比较问题。目标是展示 AI 应用工程、数据建模和评估能力。

## 当前实现

本地交互界面已可用：先运行 `.venv/bin/python local_db.py start`，再运行 `python3 server.py`，打开 http://127.0.0.1:8767 。支持条件编辑、三类结果、证据详情、最多三个候选并排比较、历史数据切换及 JSON 导出。服务只绑定本机；未部署到公网。[模型配置与启动步骤](local-setup.md)。

本地 Python 核心包含三态硬条件筛选、月度费用下界、按证据组织偏好及来源校验。已增加 UCI 历史租房数据导入、PostgreSQL 持久化、pgvector 向量与关键词混合检索，以及自然语言需求解析、证据抽取和推荐解释的模型接口。模型配置已验证，gpt-4.1-mini 已跑通虚构案例的需求解析、证据抽取与解释。该结果仅为开发冒烟验证，不代表独立评估效果。默认演示仍使用人工虚构案例；另已在本地导入 148 条芝加哥历史广告，详情见 [数据来源](data-sources.md)。

```sh
cd choice-match
python3 demo.py
python3 -m unittest discover -s tests -v
```

数据库模式使用 requirements.txt 中固定版本的 Psycopg；规则演示仅使用 Python 标准库。`demo.py` 输出远程办公与休假两组需求下的候选、待核实项及排除理由。结果中的分数是透明规则分，不是概率或经过校准的匹配百分比。

## 产品流程

用户描述需求 → 确认解析后的条件 → 查看候选 → 展开来源与缺口 → 修改偏好后重新排序。

目标架构与开发顺序见 [项目计划](plan.md)。尚未创建 GitHub 远程仓库或部署。真实资料、凭据及未获公开授权的数据不纳入样例。

## 检索与模型管线

```sh
# 无需模型，运行本地关键词检索和人工标注冒烟案例
python3 cli.py search --topic quiet
python3 evaluate_retrieval.py

# 先在项目 .env 中填写 OPENAI_API_KEY、OPENAI_MODEL
python3 cli.py parse '两卧室，允许养猫，每月总费用不超过3500美元，希望安静' > data/private/requirements.json
# 检查和修改 requirements.json 后再运行
python3 cli.py rag --requirements data/private/requirements.json --data data/private/chicago.json
```

首次使用先创建 `data/private` 目录。没有数据参数时使用虚构样例。启动时自动加载项目目录的 .env；已有环境变量优先。parse 调用一次模型；rag 对最多五个候选分别调用抽取，再调用一次解释，可能产生 API 费用，并会发送相关文本到 OpenAI。请求设置 store=false，不表示服务商零保留。

配置 DATABASE_URL 后，页面使用 PostgreSQL 数据和混合检索，从全部通过或待核实的候选召回最多 5 个供模型深入分析；结果标记 truncated。旧的显式 JSON CLI 路径保留关键词基线。数据库、来源更新与索引设计见 [数据库说明](database.md)。

规则比较结果是权威结构，模型解释不能修改其顺序；系统校验解释引用是否属于对应候选和主题，但不能保证解释在语义上得到充分支持。证据条件和日期被保存，尚未自动判定过期或条件适用性。

68 项测试已通过（包括 5 项真实 PostgreSQL 集成测试，默认运行时这 5 项跳过），包括假模型契约、API 请求结构、接口参数、失败路径和评估指标；4 个手工标注的检索冒烟案例只检查预期行为，不是独立测试集，也不是模型准确率。

新增 30 条冻结合成文本的三路检索开发评估：本次关键词、向量、混合检索的 Recall@5 分别为 50%、95%、80%。当前混合检索存在关键词干扰及无关候选进入短名单的问题，不能据此声称推荐质量达标。可复现脚本、原始结果、评估边界见 [检索评估](retrieval-evaluation.md)。

## 真实模型验证

运行 `python3 live_smoke.py` 会进行付费模型调用，仅使用虚构案例，并将完整报告写入被 Git 忽略的 `data/private/live-smoke.json`。该脚本检查需求解析、六条人工标注证据、硬条件排除和缺失费用；不自动评判解释的语义质量。验证结果和发现见 [联调记录](live-validation.md)。

## 原问题向量检索实验

页面现将完整原话传入 RAG；原问题向量作为独立信号加入候选检索排序，不新增场景细节字段、不增加主题命中数。主题最大片段分按用户权重取平均并归一化，再与原问题最大片段分按实验权重 80/20 融合；仍以主题命中数优先。已完成六个合成场景的真实嵌入对照：原问题路线带来场景信号，但当前融合没有改善前五名召回。结果及浏览器传参验证见 [原问题检索评估](original-query-evaluation.md)。设计讨论、公式、边界和面试叙事见 [ADR 001](decisions/001-original-query-retrieval.md)。

新增候选排名融合实验已完成，固定原问题权重 20%：场景召回有局部改善，但未通过预设门槛且仍落后于纯主题向量，默认排序保持不变。[冻结协议、逐例结果与限制](fusion-evaluation-v2.md)。

## 检索实验室

运行 `.venv/bin/python scripts/preview_lab.py` 后打开 http://127.0.0.1:8789/lab （临时预览五分钟）。可以在八个模拟问题上切换五档原问题权重，查看候选进出、风险变化、分数组成并导出。所有结果离线预计算，无额外 API 调用，不修改正常推荐配置。[分析方法、实测取舍与使用说明](weight-lab.md)。

来源相关性独立实验已建立；首次实测因引用校验失败提前停止，正式推荐未启用该判断层。76 项测试通过不等于语义评估通过。详见 [实验边界、停止结果与下一步](source-relevance-experiment.md)。

后续 v2 已实现按来源 ID 本地绑定短原文，并完成新材料诊断：风险材料仍有遗漏，第四批标签一致性校验失败，因此不启用自动过滤。当前 83 项测试通过。[v2 结果及标注边界](source-relevance-v2.md)。

2026-11-23：增加支持/风险/缺口摘要及独立的人工审核文字冲突排除模块，91 项测试通过；模型自动淘汰及网页审核尚未启用。[风险筛查设计与离线演示](risk-first-recommendation.md)。

页面现已支持查看风险摘要、按引用原文主动排除候选及撤销。用户决定只保留在当前结果，可随 JSON 导出；修改条件或刷新后清除。94 项回归测试通过，浏览器验证了排除/撤销/失效流程。[操作与边界](risk-first-recommendation.md)。
